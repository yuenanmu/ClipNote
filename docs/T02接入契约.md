# T02 接入契约与实现约束

本文记录可复用技术约定，不维护另一套任务进度。实际结果、版本时点及未测条件以[任务清单 T02](任务清单.md#t02--关键接入可行性及环境锁定)为准。运行入口见[验证工具说明](../project/README.md)。

## 1. 固定运行环境

最小验证包固定 Electron 45.0.0、pi-ai 1.4.0，使用 package-lock.json；Electron 内置 Node 为24.22.0，满足 pi-ai 声明的 Node >=22.19.0。开发机 Node 为24.14.1。

T02 的探针使用独立 ESM 脚本，不提前创建 React/Vite 界面或业务模块；后续 App 仍按 Electron + React + TypeScript 设计实施。

Electron 主入口不能在顶层 await app.whenReady() 形成启动互锁；探针通过 ready 回调执行异步工作。Electron 45 使用 safeStorage 的异步接口：isAsyncEncryptionAvailable、encryptStringAsync、decryptStringAsync，解密结果读取 result 字段。后续凭据存储沿用受支持接口，不复制旧同步示例。

参考：[固定 Electron 发行](https://releases.electronjs.org/release/v45.0.0)、[Electron ESM](https://www.electronjs.org/docs/latest/tutorial/esm)、[pi-ai 包声明](https://github.com/earendil-works/pi/blob/v1.4.0/packages/ai/package.json)。这些资料不代替本机结果。

## 2. API 和订阅

- API 用 createProvider + openAICompletionsApi 建立明确的兼容服务连接；CLIPNOTE_API_BASE_URL、CLIPNOTE_MODEL 和 CLIPNOTE_API_KEY 三项均需显式配置。通用密钥不能被发往隐含默认地址。
- 验证只发合成短文本，实际输出必须有文本且正常结束；失败、取消、截断和空输出都不能记为成功。关闭 SDK 自动重试，避免探针不明确地追加请求。
- 订阅用 openaiProvider 和 models.login，应用名为 ClipNote，host UUID 在本项目忽略目录内稳定保存。先获取当前账号目录，再选择 SDK 能识别的可见模型请求，不把静态目录当权限证明。
- T02 不建立长期凭据库：令牌仅在探针进程内存，完成后清除并退出。保护能力只用合成值往返检查；安全持久化、重启恢复、刷新、远端撤销及完整身份验证属于 T08，不因一次请求成功而视为完成。
- 需要人工授权时只走浏览器回调，不要求在聊天粘贴验证码、密码或回调 URL。端口占用/取消/超时需记录真实失败，不读取其他 App 的令牌。
- 报告只保留固定错误类别与已观察的 HTTP 状态。SDK 错误文本不直接输出；资格/配额只识别固定代码白名单。未知错误仍为通用失败，不能从错误字符串推断不存在的账号信息。

参考：[pi-ai 文档](https://github.com/earendil-works/pi/blob/v1.4.0/packages/ai/README.md)、[OpenAI 登录流程](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)。后续生产登录仍须逐项核对官方身份、权限、刷新与退出要求，不能只复用探针的临时内存方案。

## 3. SmartSub 启动

研究基线为官方 v3.11.0。Windows 安装应包含 SmartSub.exe 和 resources/automation/cli.cjs；官方 smartsub.cmd 是启动入口，依赖完整程序。

验证工具通过可执行文件路径和参数数组，在子进程环境设置 ELECTRON_RUN_AS_NODE=1，执行应用自带的 cli.cjs；不拼接 shell 文本，不改 PATH，不安装 MCP，不修改其他客户端配置。CLIPNOTE_SMARTSUB_DIR 可指定已有安装路径。

当前工具只有 help 探针，不能把 help 成功算作真实任务/字幕验收。未发现安装返回 not-run/退出2，不自动下载软件、识别引擎或模型。

## 4. 后续 CLI 任务调用

命令操作以官方 catalog/schemas 为准；CLI 的空格形式对应点分操作，例如 downloads start 对应 downloads.start。复杂输入使用 --input-json - 从标准输入发送，--json 获取紧凑 JSON；日志/错误走 stderr。

### 下载输入

downloads.start 的输入是 config 对象加 requestId，而不是直接发送 URL 数组。v3.11.0 的最小设计样例：

```json
{
  "config": {
    "name": "ClipNote",
    "savePath": "D:/a-user-selected-cache",
    "quality": "best",
    "engine": "auto",
    "writeSubs": true,
    "entries": [{ "url": "https://example.invalid/a-video" }]
  },
  "requestId": "a-stable-submission-id"
}
```

以上只是契约样例，不是已执行命令。savePath 要替换为明确的本地绝对位置；不默认使用 Obsidian 库。首版字幕优先，autoChain 不需要时省略；其类型是可选对象，不能错误传 false。

### 跟踪、取消与字幕

- 耗时操作返回持久化任务 ID；用 tasks.get/tasks.wait 查询，等待单次最多25秒。超时不取消后台任务，不能把关闭 CLI 当作任务已停止。
- 同一请求重连前先查 taskId；requestId 在输入相同时复用，避免重复提交。后台中断须按真实状态处理，不自行重做已有成果。
- tasks.cancel 只针对指定任务。不得强杀共享 SmartSub 后台来取消一个任务。
- 下载调度结果包含 outputPath/outputPaths 及 subtitlePaths；后续须在实机核对任务回执的外层封装与产物登记，不能假定这些字段直接出现在 CLI 顶层。
- subtitles.read 使用 filePath、offset、limit，limit 为1～500；片段时间为毫秒，返回内容 version。ClipNote 只需读取，不修改 SmartSub 原字幕。
- 无字幕才进入 transcribe/适用 pipeline，模型/引擎按需确认。断网、缺依赖、版本不符与读取失败均不能显示成功。

源码核对：[自动化说明](https://github.com/buxuku/SmartSub/blob/v3.11.0/docs/docs/guides/automation.md)、[操作目录](https://github.com/buxuku/SmartSub/blob/v3.11.0/automation/catalog.ts)、[下载输入 schema](https://github.com/buxuku/SmartSub/blob/v3.11.0/automation/schemas.ts)、[产物登记](https://github.com/buxuku/SmartSub/blob/v3.11.0/main/helpers/videoDownload/scheduler.ts)。未安装时这些只证明静态契约，真实 CLI 调用和外层回执仍须补测。
