# ClipNote 测试策略

> 本文定义后续实施必须遵守的测试方式，不表示测试代码或工具已经存在。本轮只补文档，未安装依赖、编写业务/测试代码或运行测试。授权、完成标记和实际证据统一见[任务清单](任务清单.md)。

## 1. 何时开始

测试随模块开发进行，不留到项目最后统一补。

| 阶段 | 测试工作 | 当前边界 |
|---|---|---|
| T02 最小接入验证 | 在获准环境中验证 Electron/pi-ai 兼容、API 与订阅真实文本请求、SmartSub CLI 契约；保留最小可重复验证步骤 | 不是完整 App，也不把外部失败强行包装为单元测试失败 |
| T03 首批业务实现 | 先建立轻量测试入口、合成夹具和临时目录规则，再按行为写来源解析与 IPC 测试 | 自动测试工具及实际命令在此创建并验证 |
| T04～T10 各模块 | 每个行为与修复都配套适用测试，模块完成前运行相关回归；外部接入单独真实验收 | 不等 T11/T12 才补测试，不只验证正常路径 |
| T11 跨模块恢复 | 检查点、中断、重启、取消、切换服务、资源清理与性能实测 | 补齐跨模块组合场景，不代替已有模块测试 |
| T12 安装包交付 | 目标 Windows 上安装、启动、完整工作流、卸载及数据保留 | 开发环境通过不能代替安装包通过 |

行为逻辑和 bug 修复优先采用“写出目标测试 → 确认因目标行为缺失而失败 → 实现/修复 → 测试通过 → 必要整理后回归”。失败若来自工具未配置、语法错误或缺少密钥，不能声称已经证明目标行为失败。

纯文档、布局微调等采用相称的检查，不为凑数量编写照抄实现的测试。登录、外部程序和安装器需要人工步骤时明确记录，不强求所有场景自动化。

## 2. 测试分层

| 层次 | 测什么 | 环境与调用约束 |
|---|---|---|
| 单元测试 | 解析、定位、分块、引用校验、状态转移、文件名等确定性行为 | 默认离线，使用合成输入与可控时间/ID；不调用真实 AI/SmartSub |
| 本地集成测试 | 文件写入/恢复、模块契约、IPC 及 CLI 适配边界 | 使用独立临时目录与可控服务/进程替身，真实文件系统行为不能全部模拟 |
| 界面与端到端检查 | 选文件、开始/取消、错误提示、版本选择、标题树和正文定位 | 可以先用替身稳定检查界面；它不证明真实外部接入成功 |
| 外部真实验证 | API、订阅、SmartSub CLI 与代表链接的实际结果 | 另行获准对应实施任务后显式运行，标注真实服务、版本及环境 |
| 安装包验收 | 无开发 Node 的 Windows 上运行与数据保护 | 在真实安装包执行，不以开发服务代替 |
| 笔记质量验收 | 忠实来源、关键论据/例子/限制、层级和引用可用 | 用代表性真实来源人工对照；不只比较输出字符串或判断文件存在 |

正常、异常、取消和恢复分别验证。模拟结果通过只代表所测逻辑通过，不能替代真实登录、CLI 或笔记语义验收。

## 3. 模块测试与需求对应

模块职责详见[模块索引](模块/模块索引.md)，下表定义最低行为覆盖。具体用例及完成证据放关联任务，不在本文重复维护进度。

| 场景 | 模块/任务 | 必须验证的行为 | 关联需求 |
|---|---|---|---|
| V01 桌面与桥接 | M01；T03/T07/T08/T12 | 白名单参数、无效调用、文件选择取消、凭据不出 IPC/日志、窗口隔离；打包后的实际启动 | R01/R04 |
| V02 文件来源 | M02；T03 | 四格式正常输入；时间戳/段落定位；空文件、损坏格式、编码/换行、中文/空格路径；保留原文与稳定片段 ID | R02/R05 |
| V03 SmartSub | M03；T02/T10/T11 | 安装发现/手选、版本不匹配、缺资源/拒绝下载、参数与 JSON、退出码/任务终态、读取字幕、已有后台、取消/重连；字幕优先 | R03/R09/R10/R11 |
| V04 AI 分析 | M04；T06/T07/T08/T09 | 短文/长文/超长段落，重叠去重、截断、错误结构/引用；两种真实鉴权、刷新/退出、权限/配额失败；不自动切费率路径 | R04/R05/R08 |
| V05 保存与版本 | M05；T04/T09/T11 | 新版本不覆盖人工编辑；重名、目标不可写、写入中断、来源可追溯、迁移目录；保存失败不重跑 AI | R07/R08 |
| V06 Markdown 阅读 | M06；T05/T09 | 无标题/重复/跳级标题、代码块/frontmatter 伪标题；树与正文定位一致；外部刷新、安全渲染、离线独立阅读 | R01/R06 |
| V07 任务与恢复 | M07；T09/T11 | 单任务状态、来源/分块/合并/保存检查点、重复操作、重启/重试、手动切服务归属；不重复下载/转写，不杀共享后台 | R08/R10 |

V03 关注 ClipNote 调用 SmartSub 是否正确。下载网站适配沿用上游，不把网站名单作为用户前置答复；用少量上游支持的真实链接覆盖接入路径，明确上游限制。

## 4. 测试文件与命令约定

以下是计划位置，当前均未创建：

- `project/tests/unit/`：按 source、storage、analysis、jobs、reader、desktop 分组的确定性测试。
- `project/tests/integration/`：真实临时文件、模块契约、IPC 和 CLI 适配集成检查。
- `project/tests/e2e/`：界面和安装后代表流程；外部真实验证与默认离线检查分开。
- `project/tests/fixtures/`：可公开的合成字幕、文本、Markdown 和服务返回样例。
- `project/tests/helpers/`：临时目录、可控时钟/ID、服务/CLI 替身等少量公共辅助。
- `.local/test-artifacts/`：开发期本地日志/截图等产物，已忽略，不保存密钥或私人原文。

测试与产品源码同在 `project/`，同一工作分支提交。真实私有样本和输出保存在仓库外。无需一次创建所有空目录；首次有对应测试时创建。

工具和精确版本在 T03 建测试入口时按已锁定的运行环境选择，不在文档中虚构现成命令。计划将单元、本地集成、界面、真实外部验证及类型检查分别提供脚本入口；这些入口未实现前不得执行或记录为通过。建立后由工程任务在项目索引登记真实脚本、执行目录、环境前提与成功判据，并同步本文。

当前命令状态：测试、类型检查和打包脚本均未创建；没有任何已经通过的产品测试。本次 Markdown 一致性核对不是产品测试。

## 5. 数据、安全与可重复性

- 默认测试不联网、不需要 API 密钥或订阅登录；外部真实验证必须显式选择，不混入每次本地回归或自动消耗额度。
- 来源夹具使用合成或明确可公开材料。测试不扫描整个 Obsidian 库、不访问真实凭据文件、不写默认笔记输出目录。
- 文件系统测试只用本次测试创建的独立临时目录；清理前核对所有权与范围，不因失败递归清理用户目录。
- 时间、随机 ID、网络失败及 CLI 返回可控制，降低偶发失败。错误不能靠无界重试隐藏；确需重试时记录次数、原因与最终状态。
- 不以无意义延时替代等待条件。端到端等待实际事件并有超时，失败保留经脱敏的诊断信息。
- 不为让测试通过而删除断言、放宽来源规则或默认跳过失败；快照变更需核对语义及原因，不盲目全量更新。
- 不设未经分析的统一覆盖率百分比。优先覆盖来源完整性、版本保护、引用有效性、错误恢复和敏感数据边界；覆盖率不能代替行为验收。

## 6. 每项任务的检查顺序

用户授权实施任务后，执行者负责运行该任务范围内的适用本地检查，不把“记得运行测试”交给用户盯守。真实账号登录等必须人工参与的环节明确提示；不扩大既有授权到新安装、付费请求或远程操作。

1. 开工：把任务验收映射为用例，说明新增/修改哪些测试、哪些必须真实环境、哪些尚缺条件。
2. 开发中：先验证目标失败，再实现并运行最小相关测试；跨模块契约变更同时验证直接上下游。
3. 任务收尾：运行新增/修改测试、受影响模块回归、适用类型/静态检查；记录哪些检查不适用及理由。无需为纯文档或低影响调整重复整个产品测试。
4. 申请合并前：在最新候选内容运行已建立的离线回归；契约、运行环境、登录、资源路径或打包配置变化还要补相应集成/实机检查。不能沿用旧提交的通过结果。
5. 安装包交付：运行 T12 的目标 Windows 验收。普通模块提交不要求每次都制作安装包，但相关打包路径变化要有适当证据。

检查失败先定位、修复、复跑。未具备条件的真实场景标为未运行/阻塞；不影响的局部工作可以在既有授权内继续，但涉及未满足关键验收的主任务不得勾选完成，不能静默跳过后申请完成合并。

文档约束目前不是技术上的合并保护。T03 建立可重复检查入口，后续若需要 CI/强制检查另行授权，不因此创建远程或修改全局配置。

## 7. 验证记录与勾选规则

在关联任务的实际验证记录填写：

| 字段 | 必须记录什么 |
|---|---|
| 对象 | 任务编号、模块/场景 V01～V07、实际分支和候选提交；有未提交改动时说明范围 |
| 环境 | 时间/时区、执行目录、系统/运行时版本、相关模型/CLI 版本 |
| 方法 | 实际命令或可复现人工步骤、合成/真实样本类别、必要前提 |
| 结果 | 通过/失败/未运行/不适用，退出状态及失败或跳过数量；不适用须有原因 |
| 证据 | 关键断言、必要的脱敏日志/截图位置；不贴令牌、密钥和私人全文 |
| 遗留 | 未测条件、影响、下一步及是否阻塞主任务/合并 |

只有满足任务验收并有相应证据才能勾主任务。允许部分子项先完成，不能把尚未安装 SmartSub 或没有触发令牌刷新写成“全部通过”。代码已提交、测试报告已生成或模型声称没问题都不等于验收满足。

## 8. 测试与模型审阅的关系

自动测试验证可执行行为，代码审阅寻找设计遗漏与未覆盖风险，两者互不替代。审阅修复后重跑受影响测试；会改变结论的修改还需重新审阅，记录对应代码版本。

当前本轮仅授权测试文档，不额外设定“必须 Astra”或启动任何审阅 agent。若后续采用指定模型的独立审阅，主执行环境必须实际支持并明确指定，记录实际模型、范围、结论及未解决问题；不能仅在 AGENTS 写了模型名就宣称已经切换或审阅完成。未获准或未完成的审阅不得伪报。

项目边界、分支与合并仍按 [AGENTS](../AGENTS.md) 执行；本策略不授予实施、登录、安装、调用真实服务或合并权限。
