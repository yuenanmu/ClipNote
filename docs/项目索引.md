# ClipNote 项目索引

> 本文记录已确认需求和规划入口，不代表功能已实现。任务授权、进度、验收与实际验证统一见[任务清单](任务清单.md)。

## 1. 目标与目录

ClipNote 面向个人 Windows 使用，把视频字幕或已有文本整理为忠实、详细、层级清楚且可追溯的 Markdown 笔记。独立笔记区可持久登记/切换已有 MD 与归档版本，在 Markdown 正文/标题目录和 Mindmap 间切换；用户也可以自行使用 Obsidian 等外部编辑器。

| 位置 | 用途 |
|---|---|
| 本仓库根目录 | 统筹需求、架构、任务及交接；B 路径为 `D:\Obsidian\yuenanmu\10-项目\ClipNote` |
| `project/` | 当前桌面源码、测试、依赖清单及构建配置，不另建 Git 仓库 |
| `docs/` | 项目规划与协作事实入口 |
| `prompts/` | 对话入口参考，不构成执行授权 |

| 编号 | 能力与可观察结果 | 确认依据 |
|---|---|---|
| R01 | 独立 Windows App；文件分析及本地阅读不要求安装或打开 SmartSub、Obsidian | 用户确认范围并要求三者解耦 |
| R02 | 导入 SRT、VTT、TXT、MD，整理为 Markdown；也可直接打开已有 MD 阅读 | 已确认范围 |
| R03 | SmartSub 在首版开发顺序中可后做，但首版必须完成接入；链接与文件复用分析和保存流程 | 用户明确“第一版就需要可以接入” |
| R04 | API 接入和 ChatGPT 订阅登录都必须首版可用；API 可配置地址、模型与密钥 | 用户明确两者必须纳入首版 |
| R05 | 仅整理来源，保留关键论点、论据、例子和限制；有意义的标题层级附实际时间戳或段落引用 | 用户选择仅整理来源，不补外部知识 |
| R06 | 独立笔记区持久管理外部 MD 与归档；Markdown/Markmap/可调比例对照，标题+列表+段落直接入图、正常比例逐章展开；大纲/节点定位联动，保留单独视图且首版只读 | 用户明确要求实施笔记区及后续 Markmap/对照计划 |
| R07 | 用户选择本地目录；保留来源与生成版本，重新分析不覆盖人工修改过的 Markdown | 用户选择本地文件与版本保留 |
| R08 | 服务不可用、额度或权限不足时暂停；手动重试或切换，保留已完成阶段，不自动转用付费 API | 用户选择手动切换 |
| R09 | 检测已有 SmartSub；缺失时用户点击下载官方安装器，完成一次安装后连接 CLI；可选择安装位置 | 用户接受引导一次安装 |
| R10 | 已有字幕优先；确需模型或引擎时展示用途、下载信息及位置，确认后按需下载 | 用户选择按需确认下载 |
| R11 | 网站下载兼容沿用 SmartSub；ClipNote 重点验收 CLI 调用、任务跟踪、字幕读取及异常，用上游支持的代表链接验证 | 用户最新确认优先 CLI，无需提前列网站清单 |

阅读文件不触发 AI 请求。分析前说明来源文本将发给所选服务；首次连接和切换时显示接收方。正文、凭据和令牌不进入 Git 或普通日志。

## 4. 技术决策与环境

| 决策 | 选择及理由 | 边界 |
|---|---|---|
| D01 桌面与界面 | Electron + React + TypeScript；Vite 构建界面，esbuild 构建主进程/preload/Worker | Electron45.0.0、React19.3.1、TypeScript7.0.2、Vite8.3.5、esbuild0.28.2 已锁定；NSIS 打包器留 T12 |
| D02 AI | `@earendil-works/pi-ai`；API 与 ChatGPT 登录分别适配统一文本接口 | v1.4.0 为研究基线，库有实现不等于目标账号已可用 |
| D03 来源 | 文件适配器与 SmartSub CLI 适配器并列 | 首版不采用 MCP，不抓取窗口或读取其私有数据库 |
| D04 SmartSub | 官方 buxuku/SmartSub v3.11.0 自动化接口；接入已有安装或引导官方下载 | 用户 fork 3.7.0 早于当前 CLI；CLI 依赖完整 SmartSub 运行环境 |
| D05 保存与阅读 | 本地独立版本；持久文件引用与归档并列；同一 AST 驱动正文/标题树/Mindmap | MD 原位只读，脑图不另存副本；Obsidian 可选 |
| D06 资源 | 单个活动任务、按需启动、字幕优先、按需模型、结束轮询 | 尚无实测数值，不承诺具体内存占用 |

开发机已只读检查：Windows X64，系统版本字符串 `10.0.26200`；Node `v24.14.1`、npm `11.11.0`、Git `2.50.0.windows.2`。这不等于安装包已兼容所有 Windows。

pi-ai v1.4.0 声明 Node `>=22.19.0`；Electron45.0.0 内置 Node24.22.0。B 的开发 Node24.15.0 满足清单下限。T03 沿用 Node test，使用 Playwright1.64.1 驱动项目自身 Electron，类型检查采用 tsc；安装包工具仍未创建。

实际入口在 project/：npm.cmd run build、npm.cmd start 可打开桌面；npm.cmd run typecheck、npm.cmd test、npm.cmd run test:e2e 分别检查类型、本地回归和真实窗口。T02 的 verify:runtime/verify:electron 及显式外部验证入口保留，条件见[工具说明](../project/README.md)。桌面支持文件导入、归档版本/恢复及独立 Markdown 标题树阅读，尚不进行 AI 整理或提供安装包。
