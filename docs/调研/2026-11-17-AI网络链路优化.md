# ClipNote AI 网络链路调研与决策

2026-11-17。证据来自本地产品源码、历史验收与公开一手资料。实测表留给 T19/T21/T23。P032 证明用户遇到过约 60 秒失败，既有记录无法区分首次输出延迟、连接中断与正在输出时触发总时限。[问题记录](../问题记录.md)

## 1. 两条请求路径及瓶颈

| 环节 | 现状及可核对代码 | 下一步如何证明瓶颈 |
|---|---|---|
| API 入口 | 主进程调度、预检与工作区锁，按文件启动分析 Worker。Worker 通过 pi-ai 的 OpenAI 兼容适配器调用 Node fetch。序列化、网络与模型耗时当前部分合并 | 在确认、启动 Worker、预检结束和实际送出间分别记时，判断等待是否出现在发请求之前 |
| API 响应 | 首次读取传输字节会进入 receiving，首字节可能只是头、空帧或心跳。单请求 60 秒盖住接收，文件另有 3～30 分钟和请求数预算。已有短引用、同批重复内容复用及有界修正 | 分开标头、首个非空文本和有效输出间隔，重放首输出迟到与持续输出超过 60 秒 |
| 订阅预检 | 面板、prepare、start 都可能触发模型发现。prepare 和 start 都校验账户、模型和输出计划。OAuth/刷新与推理经过 DevKit 和隔离 Electron session | 单独记录模型列表和会话检查次数及耗时。测试账户切换，区分必要的权限校验与重复请求 |
| 订阅响应 | DevKit 已支持文本 delta 和完成验证，分析适配器只使用完整结果。单次 180 秒也覆盖体，缺少同口径文件预算和分块进度。未完成的响应可能在 DevKit 抛错，需明确与纯断流、输出上限的区别 | 从 DevKit 接出脱敏事件，记录首文本、间隔、完成事件和错误类型。相同输入测量引用大小及分块次数 |
| 生成到磁盘 | 两路执行结构与引用校验。API 生成后尝试保存。订阅生成后先登记待保存。保存正发生时网络已结束 | 记录本地校验、结果暂存、保存。遇写入冲突检查第二次操作是否发起额外 AI 请求 |

| Vercel AI SDK | 将首个有效输出、输出间隔和总截止分开建模。间隔计时关注有效增量 | 借鉴语义，用现有传输和适配实现。无需迁移 SDK 便可验证 P032 |

## 3. 首轮策略及错误契约

先保留两条既有传输。T19 采集基线，T21 引入可注入时钟和单次请求计时器。下表是待实现的工程起始值，无真实服务性能承诺。实际用户环境调整交由 T23 数据支持。自动测试用注入短时限模拟跨越 60 秒，另以等效慢流场景核验。

| 计时 | 起点与推进信号 | 起始值和触发结果 |
|---|---|---|
| 首有效文本 | 推理请求准备发送时启动。响应头和非文本事件只记录，不停止计时。首个非空且非纯空白文本结束此阶段 | 90 秒。到期 FIRST_OUTPUT_TIMEOUT |
| 接收空闲 | 从首个有效文本起。后续有效文本重置，协议注释、心跳和重复空帧不重置 | 45 秒。到期 STREAM_IDLE_TIMEOUT |
| 单请求硬截止 | 请求发送起。覆盖响应体和完成事件 | 180 秒。到期 REQUEST_DEADLINE |
| 文件硬截止 | 从开始该文件的分析工作起，所有块和结构修正共用。资料预检和写盘单独计时 | 若有 N 个原始块，总时限为 min(30 分钟, max(3 分钟, N × 90 秒))，请求数为 max(8, N × 4)，拆分与修正都计入。订阅接入同一预算。到期 FILE_DEADLINE，超过次数为 REQUEST_LIMIT |

第一个到期的绝对期限胜出。同一检查点同时到期时先判断用户取消，再文件上限、请求上限及阶段时限，输出一次终态。主动取消关闭流和 Worker，迟到事件不能产生保存。若服务支持单次非流式兼容响应，首文本在完整有效正文出现时记录。流已经产生文本但缺失合法完成事件，归 STREAM_INTERRUPTED，不生成残缺笔记。协议明确指出输出上限时才进入现有有界的拆分或修正路径。结构或引用失败与网络错误分别归类。

| 服务结果 | 提示及后续动作 |
|---|---|
| 401、明确权限拒绝、订阅会话失效 | 提示修正 API 配置或重新授权，用户确认后再开始 |
| 402、额度耗尽、429 | 区分费用/可用额度与频率。可信 Retry-After 只显示建议等待，用户手动重试 |
| 5xx、网络断开、首输出或空闲超时 | 给出阶段和手动重试。SDK 与业务层维持零自动推理重试，避免重复计费 |
| 保存异常 | 使用既有暂存结果只重试保存 |

本地诊断只保留任务/尝试和请求序号、链路、输入长度档、是否暖连接、相对毫秒、状态码类别和错误阶段。成功与失败都计入分母。无法可靠观察的 DNS/TLS/服务端推理耗时标未知。保留本次测试所用应用和运行时版本。订阅权限和上游限制参考[错误与恢复](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)。

## 4. 可执行对照与采用门槛

1. **固定基线。** 先使用同一台 Windows、同一应用构建、同一合成输入、同一 mock 调度和目标目录。新增后续测试夹具，在隔离环境提供短流、慢首文本、含心跳的停滞、长但持续输出、断流、429 与取消。API 与订阅保持自己的协议格式，响应时序相同。每次另记阶段耗时、成功与否、请求数和校验结果。
2. **比传输。** 对 API 的 Node Worker 和临时 Electron 隔离会话分别测试直连、可用测试代理、不可用测试代理。每组 10 次合成请求，一半冷启动、一半同会话内连续请求。先证明实际路径，再比较成功率和首输出/总耗时分布。记录 p50 和最大值。样本达到 30 次再报告 p95。不同鉴权及模型的两条生产路径仅分别对其自身基线，不能把差异全算作网络。
3. **只在证据过线时拟切换。** Electron 路径必须稳定复现一个现有已证实的代理连通性缺口，或在同路径、同响应计划下令五组交替暖请求的延迟改善可复现。两种情况均要求全部正常样本成功，取消、限制、保存与打包回归不退化。只有耗时改善时，以首输出或总耗时中位数至少改善 20% 且最大值未恶化为进入实机复核的门槛。合成门槛负责筛选，目标机再证实才做默认变化。达不到则保留 Node。
4. **切换设计。** 若获准，API 分析和解析留在 Worker。可信主进程的独立非持久会话执行请求并通过内部 MessagePort 回传响应头、字节和终态。每条消息绑定请求 ID，Worker 按需求拉取下一片保持背压。主进程在接到中止、端口关闭、Worker 退出或时限到达时取消 reader 和网络。请求地址只允许既有设置通过校验后构建的 API 路径，请求体和凭据留在可信进程。保留禁止重定向、响应大小限制和正常证书校验。订阅继续使用原隔离会话，不混用会话或授权。
5. **SDK 和中转决策。** 若旧 SDK 无法报告语义化增量，先查可用回调或在应用适配层统一映射。只有隔离验证证明当前 SDK 明确阻碍这项能力，且目标 SDK 能通过错误、配置、校验和打包回归，才另列迁移任务。中转需要独立部署并引入新的资料接收方，现有本地目标优先排除该路线。

记录模板为“版本｜链路｜样本｜传输及代理｜连接冷暖｜请求数｜到头/首文本/完成/保存毫秒｜终态/错误阶段｜质量检查｜结论”。本轮仅完成静态与公开资料核对，表中采样、代理测试和真实账号均尚未执行。

## 5. T22 减少无效工作

| 候选 | 启用条件 | 实施与验证 |
|---|---|---|
| 订阅模型列表复用 | 同一次准备和确认在相同账号反复命中模型列表，替身请求计数证实可去重 | 按账户/profile 和会话代次缓存一次准备取得的模型列表，最长 60 秒。开始前仍核对当前身份与权限。退出、切换、刷新失败、用户主动刷新或服务拒绝所选模型时清除。模型失效重新确认，不能自动切换 |
| 订阅短引用 | 固定同源样本对照表明引用体积或校验失败下降，且所有真实细节保留 | 复用 API 短引用及严格回映，仅识别当次有效引用。对同一来源逐块比较长度、次数与完整性，遇伪造或跨块引用拒绝 |
| 订阅同批分块检查点 | 长文中断验证显示手动重试能减少已完成块的重复请求并保持结果一致 | 内存中按源校验值、账户、模型、配置和提示版本匹配，退出或改变任一身份清除。只复用已经通过校验的块。跨重启持久生成恢复另行评估 |
| 增加并发 | 后续数据证明确有批次等待需求且服务限额允许 | 本轮保持串行。将并发留作后续独立任务 |
