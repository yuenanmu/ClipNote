# M02 文件来源

## 职责与边界

导入 SRT、VTT、TXT、MD，保留原始文本/字幕，产生统一 SourceDocument 和稳定 SourceSegment。文件分析不依赖 SmartSub；已有 MD 的直接阅读走 M06，不强制重新导入或分析。

不请求 AI、不处理下载网站、不自行保存最终笔记。原始快照由存储模块持久化，解析模块不改变原意。

## 输入、输出与关系

- 输入：由 M01 选择的本地文件、解析选项。
- 输出：sourceId、来源类型/路径、格式、原始内容、有序片段和可用的时间/语言信息。
- 下游：[M05](本地存储与版本.md) 保存来源，[M04](AI分析.md) 分析，[M07](任务协调与恢复.md) 管理阶段。
- [M03](SmartSub适配.md) 是并列的来源生产者，输出相同契约，不经过文件选择界面。
- 实际位置：`project/src/modules/source/`，公共类型声明位于 `project/src/contracts/`。

## 当前接口与限制

- `parseSource(bytes: Uint8Array, originalPath: string): SourceDocument`：保留 decoded rawText 的原始换行、原始字节 checksum、格式和 encoding。sourceId 由格式和原始字节校验值导出，同一快照重复导入的片段 ID 稳定，不依赖本机路径。
- `importSourceFile(filePath: string): Promise<SourceDocument>`：只读明确选择的文件，逐块读取并限制总量，读取错误转为固定类别。
- `importSourceSnapshot(filePath: string): Promise<SourceSnapshot>`：返回 document 与同一次读取的原始 bytes；前一接口是兼容包装。字节仅在 Worker/主进程传递，renderer 只收到 document；M05 归档时直接保存该快照，不重读可能已修改或删除的原文件。
- 片段含 order/text、startLine/endLine、startOffset/endOffset（结束字符偏移不包含端点）；字幕带实际 startMs/endMs，TXT/MD 不生成时间。未保存快照在内存，明确归档后持久化到 M05 的版本目录。
- 支持 UTF-8、带 BOM 的 UTF-16 LE/BE、GB18030；不能可靠解码、空文件、坏时间、缺 cue 分隔或 VTT 头部损坏时明确报错，不丢弃部分字幕后报成功。
- 文件最多16 MiB、片段最多20,000。逐行生成器只保留当前块必要的首尾范围，不为全部短行建立常驻对象数组。

## 来源契约

字幕片段保留起止时间、顺序及原文；时间只取自实际来源。TXT/MD 保留段落/行或字符范围，不虚构时间。片段 ID 在同一来源快照中稳定，分块和合并不能改成无法回查的新 ID。

MD 作为分析来源时保留原文；MD 作为阅读输入时由 M06 直接解析。规范化可以统一换行/时间格式，但必须保留原始快照及定位关系。

来源包含的“忽略规则”“执行命令”等只视为文本，不影响应用权限或模型的系统约束。

## 错误与验收重点

覆盖空文件、损坏时间、缺失文本、常见编码/换行、超长单段和中文/空格路径。可恢复异常需说明影响，不静默丢弃大量内容；无法可靠解析则停止分析并提示。用合成夹具检查规范化与原文定位，避免真实私有字幕进 Git。
