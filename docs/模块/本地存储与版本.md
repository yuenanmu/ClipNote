# M05 本地存储与版本

## 职责与边界

持久保存来源快照、生成的 Markdown 和引用元数据；创建独立版本并处理保存失败/恢复。重新分析不覆盖人工编辑，缓存清理不损害来源追溯。

不理解 AI 私有大纲，不调用服务，不解析网站，不管理凭据。凭据保护由 M01 负责，任务阶段由 M07 负责。

## 输入、输出与关系

- 输入：来源快照、待保存 Markdown、引用与生成元数据、用户输出根目录。
- 输出：SavedRevision，包含来源/版本 ID、笔记/来源/manifest 路径、时间、归档类型和 noteModified 外部修改标记。
- 来源来自 [M02](文件来源.md)/[M03](SmartSub适配.md)，正文来自 [M04](AI分析.md)；也可使用合成正文独立开发与验收。
- [M07](任务协调与恢复.md) 调用保存/恢复，[M06](Markdown阅读.md) 读取已提交版本。
- 实际位置：`project/src/modules/storage/`，公共类型位于 `project/src/contracts/storage.ts`；主进程控制器和 Worker 位于 `project/src/main/`。

## 当前接口

`StorageService(stateDir)` 提供 `chooseDirectory(parent)`、`state()`、`save(snapshot, markdown, metadata)`、`resume(draftId)` 和 `open(sourceId, revisionId)`。所有调用由应用串行调度；同一 userData 通过 Electron 单实例锁排除多个应用进程并发使用，不把服务类宣称为多进程数据库。

SourceSnapshot 包含 SourceDocument 与导入时的原始字节；保存不重读原始文件。RevisionMetadata 只接受 kind、provider、model、promptVersion、sourceRefs，拒绝未知字段，引用必须属于该来源；不接收 API 配置或任意对象。当前 UI 只调用 source-archive 原文归档，generated-note 为后续生成模块预留，使用合成正文验证。

LibraryState 返回选定目录、可打开版本、恢复草稿和读取警告。打开版本从归档字节重新解析来源，原路径仅作追溯；不依赖原文件仍存在，不代表已提供 Markdown 阅读器。

M06 已通过 `open` 校验版本后读取实际 note.md；外部编辑的正文允许阅读，来源链接仍只定位该归档的有效片段。阅读/刷新不创建或改写任何版本；来源缺失/损坏时无法作为有效归档打开，用户仍可通过独立 Markdown 选择框查看自己明确选择的笔记。

## 保存契约

输出位置由用户选择，不默认代码仓库或整个 Obsidian 库。选择父目录后创建 `ClipNote/`，也可直接选择带有效 `.clipnote-library.json` 标记的已有库；拒绝接管未知同名目录。仅遍历库内 items，不扫描父目录其他资料。原视频是单独缓存，不默认复制进笔记。

```text
ClipNote/
  .clipnote-library.json
  items/<sourceId>/
    item.json
    revisions/<revisionId>/
      .owner.json
      source.<srt|vtt|txt|md>
      note.md
      source.json
      manifest.json
      .committed
```

来源 ID 由格式和内容校验值导出，版本使用独占创建的 UUID 目录，并记录创建时间；碰撞明确失败，不覆盖。文件名固定，管理路径逐级检查且拒绝链接/junction。manifest 使用相对文件名，记录来源/正文/元数据 SHA-256、模型/服务标识、提示词版本及片段引用，不含密钥或令牌。source.json 的原绝对路径是历史信息，不用于实际打开文件。

先在本机 stateDir/drafts/<draftId> 持久化完整输入，以 `.prepared` 标记可恢复；再在目标盘独占版本目录内写入并刷新文件，读回校验后最后创建空 `.committed` 标记。这是发布协议，不依赖跨盘改名，也不承诺任意硬件断电下的事务性。未提交或文件损坏的版本不进入成功列表，目标残留不冒充成功。

draft 保存 source.bin、note.md、source.json、draft.json；attempt.json 记录目标库与版本 ID。提交成功但回执前中断时，同一库重试先确认上次提交，避免再建版本；普通失败保留完整草稿，允许重启或改目录后重试，不再次调用 AI。完成后写 `.done` 再清理固定草稿文件；扫描先过滤完成标记，再计算1,000份恢复列表上限，避免历史墓碑隐藏待恢复工作。草稿准备完成前失败明确报错，此阶段不能保证重启恢复。

用户可以外部编辑 note.md；校验值变化用于识别修改，不把人工编辑静默覆盖或修复。再次分析始终创建新版本。

开发 stateDir 为 `.local/desktop/storage/`，settings.json 只保存所选库路径；自动窗口测试使用各自隔离目录。库迁移后重新选择库目录，内部相对引用继续有效。列表读取失败向界面报告；刷新失败不当作已确认版本保存失败。当前最多检查1,000个版本，界面显示最近100个版本，超限/坏数据返回警告。

## 错误与验收重点

覆盖目录不可写、空间不足、重名、中文/空格路径、写到一半中断、来源缺失及目录迁移。不损坏已有版本，错误后保留能恢复的结果，只清理任务实际拥有的临时目录。

开发验收用合成来源和 Markdown，因此本模块无需等待 AI 实现。真实私有来源、笔记和运行缓存不进入 Git。
