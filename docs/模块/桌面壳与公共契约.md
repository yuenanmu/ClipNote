# M01 桌面壳与公共契约

## 职责与边界

提供 Electron 主进程、React 界面入口、受限 preload、文件选择、系统外部打开及本地凭据保护。集中维护跨模块数据类型和 IPC 消息。后续 Windows 安装包在此确定启动与打包边界。

不承担字幕解析、提示词生成、CLI 业务流程或笔记版本保存。React 不直接读取密钥、运行 shell 或持有任意文件访问权。

## 输入、输出与关系

- 输入：用户操作、文件选择结果、模块命令和任务事件。
- 输出：受约束的主进程调用、界面状态、必要的配置摘要；凭据只返回非敏感状态。
- 调用 [M07](任务协调与恢复.md) 执行任务，调用 [M06](Markdown阅读.md) 直接阅读；为 [M04](AI分析.md) 提供受保护凭据存储及登录交互。
- 计划位置：`project/src/main/`、`project/src/preload/`、`project/src/contracts/`、`project/src/renderer/`。均尚未创建。

## 核心约定

- 开启 contextIsolation/sandbox，关闭 nodeIntegration；界面仅访问白名单能力。
- 公共契约沿用架构中的 SourceDocument、Job、Profile 等名称；具体领域语义由所属模块维护，不能在 IPC 两端分别发明字段。
- 文件路径来源于受控选择或已登记的笔记，校验访问范围；不执行用户文本中的命令。
- API/OAuth 凭据在用户应用数据目录加密保存，刷新写入串行化；保护能力不可用时报错，不降为明文。
- pi-ai 的运行下限要与 Electron 内置 Node 一起验证；开发机 Node 能运行不等于安装包能运行。

## 错误与验收重点

窗口关闭、重复操作、桥接参数无效、文件取消选择、凭据解密失败、登录回调中断都需明确响应。界面不因耗时解析/CLI/网络调用而卡住；敏感值不经 IPC、日志或导出泄露。安装后在无开发 Node 的目标环境验证实际启动能力。
