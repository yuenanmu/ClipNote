> 本文是任务授权、状态、验收及实际验证的唯一记录来源。项目能力见[项目索引](项目索引.md)，模块契约见[架构](架构.md)。范围确认不等于授权立即实施。

## 1. 授权与编排规则

- 主任务复选框是唯一完成标记：`- [ ]` 未完成，`- [x]` 已完成；已完成标题可划线。未勾选任务的进行中/阻塞情况在任务记录说明，授权单独记录。勾选前须验收并有证据。
- T01、T13 为此前完成的文档任务。本轮只授权 T14：补充测试策略和相关文档；不修改 Git 状态。T02～T12 仍待用户另行授权实施。
- 编号稳定不复用。负责人默认未指派；获准后明确一个主执行者，其他 agent 可只读调查和审阅，主执行者汇总进度与证据。
- P0 表示先排除关键接入风险，P1 表示核心工作流，P2 表示整体验证与交付；这些任务都服务首版，P2 不等于可从首版删去。
- 后续每项任务先把行为验收转为适用的测试或人工步骤，再实施并核验；命令从实际创建的配置取得，写入检查时点、目录、结果和证据。不得预填“通过”。
- 不能满足关键验收就保留未完成/阻塞。模拟服务、合成字幕有助局部验证，但不能替代真实登录、SmartSub 或网站验收。
- 测试按[测试策略](测试策略.md)分层，模块最低覆盖 V01～V07 与任务关联；测试记录仍只在本文维护。T02 验证接入，T03 建入口，后续逐行为写测，T11/T12 不替代前期测试。
