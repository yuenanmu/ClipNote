### 首轮优先处理 P032

用户复测时，字幕文件已进入 API 整理，设置页的固定短文本测试通过。实际单文件第 1/1 块在第 1 次请求约 60 秒时失败，界面同时显示整份资料上限 180 秒。源码为 API 单请求设定 60 秒，单块文件预算至少 180 秒；订阅 DevKit 单请求为 180 秒。旧界面收到任意响应字节就显示正在接收。此次截图无法确定有效正文是否已经到达，也无法区分服务端与传输耗时。[问题记录](问题记录.md#p032ai-整理在固定-60-秒请求时限失败仍待处理)

1. **复现并记录基线。** 在 `tests/unit/api-provider.test.ts` 与 `tests/integration/subscription-stream-fixture.ts` 用同一套受控时序覆盖正常短流、先到响应头与心跳、首文本迟到、跨过旧 60 秒仍输出、首文本后停滞和中途断流。记录开始、响应头、首个及末次有效文本、结束、请求次数和失败类别。先复现旧行为，并标明真实样本还缺哪些证据。
2. **分离期限。** 在 `src/modules/api/provider.ts`、`src/main/analysis-task.ts`、订阅适配器及 `vendor/siwc/src/responses.ts` 接入同一语义的首输出、接收空闲、单请求硬截止和整份资料预算，沿当前取消信号传递。请求发出后等待首个非空正文，随后仅由有效正文刷新空闲计时。各硬期限从各自开始点计算。阈值在实施时依据合成时序和经授权的测量定稿，记录两路默认值、配置归属、依据及回退方法。
3. **验证错误与结果完整性。** 分别验证首文本超时、接收停滞、请求或文件硬截止、断流、用户取消、限流和服务错误。持续有效输出超过旧 60 秒且仍在新预算内时，必须完成校验和保存。失败与取消各只有一个终态，迟到输出不得落盘，网络超时不得自动重发。保留原有受限结构修正和同批检查点；写盘失败继续使用待保存结果。
4. **独立评估传输。** 在原传输策略通过后，再用相同模型、输入、请求参数和时限对照直连、可用代理和不可用代理。记录首有效文本、接收间隔、总耗时、成功率、请求次数及内容完整度。证据明确指向传输且收益可复现时，再决定是否引入 Electron 会话桥接。

### 窗口与真实样本验收

T20 首先在现有整理入口呈现任务阶段和失败原因，再扩展集中任务、保存与视频入口。显示等待首个有效输出、接收正文、校验和保存，并区分单请求限制与整份资料预算。点击失败任务能看到已到达的阶段、相对耗时、所用服务和可执行操作。连接测试说明固定短文本的覆盖范围。已取得的字幕可直接重试整理；写盘失败可恢复保存。任务阶段绑定任务 ID，切页后仍可查询，旧尝试的迟到事件不得更新新任务。

T23 在获准使用真实服务后，用同一份脱敏字幕分别验证短文本、原长度和批量重复资料，记录服务、模型、输入规模、请求数、首有效文本时间、总时间、终态与笔记完整度。确认截图对应的长资料能够完成，或能说明失败阶段与原因。受控测试与真实样本结果分别登记；诊断中仅保留脱敏阶段、耗时、类别与数量。
