## 目标和范围

双链路同等优先，集中展示从来源到结果的全过程。保留论点、论据、示例和限制的详细程度。两路均在确认目的地后自动保存，覆盖须获得明确同意并复核磁盘状态。继续使用现有测试、凭据保护、目录、校验、生成结果和阅读契约。第一阶段继续限制一个活跃 AI 任务，批次串行。订阅批量、跨重启自动继续生成、切换 SDK 和云中转暂不列为交付要求。

## T19 统一测量与任务快照

**入口。** 从 `src/contracts/analysis.ts`、`src/main/index.ts`、`src/main/analysis-task.ts`、`src/modules/api/provider.ts`、`src/modules/subscription/{analyze,adapter}.ts` 和 `vendor/siwc/src/responses.ts` 理清回调。路径相对 `project/`。保留旧面板对现有 IPC 的使用。

- 新建 `src/contracts/organization-task.ts`，利用[流程规格](第二版AI整理流程.md)定义共享快照、条目和受限错误。在主进程汇聚快照，提供只读 `organization:list` 与 `organization:get(taskId)`，沿用 trusted 校验及 preload 白名单。首批仅内存索引，任务结果仍用现有存储。
- API Worker 在保留现有请求参数、受限 fetch 和响应校验的前提下，将 completeSimple 改为消费本地 pi-ai 已提供的 models.streamSimple 事件。只用 text_delta 标记有效输出，并取流的最终结果走原校验。订阅适配器消费 DevKit 的 onDelta 并上报阶段。计时采用同一进程单调时钟计算差值，跨线程只传相对时间或计时结果。记录响应头、首个非空文本、末次输出、校验、保存与终态。合并更新频率上限 4 次/秒，终态即时发布。内容增量留在可信进程。
- 扩展 `api-provider.test.ts`、`analysis-task.test.ts`、`subscription-adapter.test.ts` 及 `subscription-stream.test.mjs`。API 和订阅都能得到有序阶段并在失败、取消时留下有效计时。检查 V2-01～02。不改时限或请求行为，这一阶段的基线用于 T21/T22。

## T20 集中任务与保存

**入口。** `src/renderer/App.tsx`、`BatchPanel.tsx`、`SubscriptionTaskPanel.tsx`、`SmartSubPanel.tsx`、`smartsub-observer.ts`、`src/main/{batch-controller,subscription-task,workspace-controller}.ts`、`modules/workspace/results.ts`。

- 在 App 增加共享任务视图，保留三个现有入口，把入口已创建的任务交给中央详情。将快照增删和生命周期集中在主进程模块，预加载桥只暴露查询与受限操作。沿用 400～500ms 查询节奏，页面卸载停止查询，快照以主进程为准。现有控制器继续执行操作，可信主进程维护快照及关联。统一列表和详情操作的主进程入口按任务 ID 转派现有取消、重试和打开能力，拒绝过期操作。用户切页时快照和执行状态仍可查询。
- 订阅复用 `OutputPlan` 与生成结果存储。确认后核对源、账户、模型和目标，分析成功先落待保存结果，再用原 OutputPlan 在主进程内生成并消费仅用于当次保存的确认令牌。批量与订阅均以新的磁盘校验结果为准。保存失败保留结果 ID，提供仅保存重试。旧待保存记录继续从原入口访问。
- SmartSub 进入同一任务详情，使用现有任务 ID 获取字幕。显式查询显示正在查询及查询结果，覆盖 P033。已经获取的来源直接进入确认，生成失败重试只走整理。
- 扩展 `tests/e2e/{batch,subscription,smartsub-task,smartsub-recovery}.test.mjs`。覆盖 V2-03～07，尤其是并行操作拒绝、保存冲突、部分成功与取消竞争。

## T21 分阶段时限与传输对照

**入口。** T19 回调、`src/modules/api/provider.ts`、`src/main/analysis-task.ts`、`src/modules/subscription/transport.ts`、`vendor/siwc/src/responses.ts`。按[调研中的实验和错误映射](调研/2026-11-17-AI网络链路优化.md)执行。

- 两路采用同一语义的首输出、有效输出空闲、单请求与文件总期限，并保留各路线真实的阶段证据。硬期限不得被心跳重置。关闭自动推理重试，保留已存在的有界结构修正；不改变服务、模型或费用来源。
- 首轮只在原传输上启用策略。随后用合成对照比较两条 API 传输。在证据达到门槛且获得该变更授权时，才实现主进程隔离会话桥接。否则继续用 Node Worker，保留测量。
- 扩展 `api-provider.test.ts`、`analysis-task.test.ts`、`subscription-transport.test.ts`、`subscription-stream.test.mjs` 和 `batch-latency.test.mjs`，验 V2-08～12。先覆盖首输出、空闲、硬截止、取消与服务错误，再比较代理和连接。原始 URL、异常正文及密钥不得出现在诊断记录。
