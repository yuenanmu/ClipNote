# ClipNote 第二版开发计划

状态：计划，尚未授权代码实施。编制于 2026-11-17；第一版基线与未验收事项见[任务清单](任务清单.md)。用户确认第一版开发和 Windows 打包完成，候选标签 v0.1.0-candidate。P032（固定 60 秒）与 P027（批量延迟）直接相关；P033（转写查询反馈）涉及视频来源阶段，保留关联，不假定属于 AI 网络问题。

## 目标和边界

一个任务内串起文件或视频来源、AI 整理、失败处理、保存与打开。API 和 ChatGPT 订阅同等优先，保留论点、论据、例子和限制的详细程度。开始前确认目标，完成后自动保存；覆盖已有文件需明确确认并检查外部变化。

本轮仅完成研究与文档。产品实现、模型或服务替换、中转部署、真实收费测试、合并和发布需单独授权。既有 API 阶段反馈、同批重复内容复用、内存分块恢复及保存失败恢复是第一版基础，不重复列为新成果。

## 推荐实施顺序

1. **统一任务状态及测量**：制定两链路共享的状态、进度和脱敏时间事件，覆盖首响应、首文本、接收、校验与保存；对现有任务状态建立兼容映射。
2. **集中流程**：按[流程设计](第二版AI整理流程.md)接入任务列表与详情，统一开始前确认、失败操作和自动保存结果入口。
3. **网络可靠性**：依照[调研](调研/2026-11-17-AI网络链路优化.md)先评估网络路径、分阶段时限和错误映射；保持取消、域名限制、凭据隔离和任务预算。
4. **减少无效工作**：测量后评估模型列表复用、订阅短引用协议、检查点及有限并发；不得为了速度删减正文细节或绕过校验。
5. **端到端验收**：两链路使用相同合成样本检查体验和异常，再由用户选择真实服务和样本验证质量、耗时与打包版行为。

每阶段形成独立任务、测试与用户验收证据，再按项目分支流程交付。前一阶段的接口确定后再实施下一阶段；网络策略需用测量确定具体数值，不能把未经验证的默认时限当承诺。

## 验收

- 单份、多份和视频来源可以从同一任务查看状态、异常、操作及最终笔记；保存冲突不会覆盖外部修改。
- 两条链路均可看到真实阶段和已耗时，支持取消；错误可区分等待、接收中断及保存失败，不虚构百分比或剩余时间。
- 慢但持续输出不因原固定时限被误判；真正停滞、限流、断流和取消有明确终态。自动重试不得导致无界等待或隐性费用。
- 相同样本对照记录首次有效反馈、总耗时、成功率、请求次数及笔记完整度；未建立基线前不承诺提速比例。结构校验不能替代原文人工质量检查。
- 相关单元、集成、窗口和打包回归分开记录；真实账号、外网及跨电脑验收不得用替身结果代替。
