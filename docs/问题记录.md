# ClipNote 问题记录

本文持续记录值得复用的问题、已验证根因和防复发办法。后续问题在同一文件追加；相同根因补充原条目，不按每次排查新建文件。记录约束见 [AGENTS](../AGENTS.md)，任务状态和完整验证事实以[任务清单](任务清单.md)为准。

每条保持稳定编号，注明日期、触发条件、现象、根因、修复及回归入口。尚未查清的原因标为待验证；不保存凭据、私人资料或原始敏感日志。

## P001：自动化截图正常，普通启动却白屏或无法操作窗口

- **发现日期与关联**：2026-10-27，T03；修复提交 `f629115`。
- **触发条件与现象**：B 电脑执行 `npm.cmd start` 后界面空白，系统最小化/最大化/关闭无法正常操作，需要终端 Ctrl+C；此前 Playwright 页面截图正常。
- **已验证根因**：交互式 Electron 的启动器设置了 `windowsHide:true`。本机普通启动下真实 ClipNote HWND 的可见状态为 false；仅将该选项改为 false 后恢复可见，系统窗口命令和正常退出回归通过。不能把它泛化为已证明的 GPU 或缓存故障。
- **修复**：[启动器](../project/tools/start-desktop.mjs) 使用 `windowsHide:false`，保留原有 shell/标准流。交互式 GUI 不沿用隐藏后台辅助进程的启动配置。
- **验证盲区**：旧 E2E 通过 Playwright 的另一条路径启动，绕过普通启动器；CDP 页面截图和 app.close() 没有验证真实 HWND 和系统标题栏。截图真实，但验证对象不足以覆盖用户使用路径。
- **防复发**：保留[普通启动回归](../project/tests/e2e/startup.test.mjs)，直接执行 npm start，不附加调试器；检查原生可见/启用状态，验证最小化、最大化、还原和系统关闭后启动器退出。原生窗口截图与页面自动化各自提供不同证据，不互相替代。

## P002：字幕缺少分隔时静默遗漏内容或错配时间

- **发现日期与关联**：2026-10-26，T03；修复已包含于 `ae8b328`。
- **触发条件与现象**：VTT 的 WEBVTT 头部与第一条 cue 没有空行，首段被当成头部丢弃；两个 SRT/VTT cue 没有分隔空行，第二条时间和正文被并入第一片段。
- **已验证根因**：解析器直接跳过首块，并将时间行后的整个块视为正文，缺少头部内容及块内第二条时间结构的验证。
- **修复**：严格检查 VTT 头部和元数据，以及字幕块中的时间结构；无法可靠划分 cue 时明确报错，不能丢掉一段内容后仍报告导入成功。
- **防复发**：[来源回归](../project/tests/unit/source.test.ts) 同时覆盖正常字幕和这些损坏边界；验收要检查片段数量、文本和真实时间归属，不能只确认函数返回成功或 rawText 仍然存在。

## P003：文件大小受限，解析内存仍可能被大量短行放大

- **发现日期与关联**：2026-10-26，T03；修复已包含于 `ae8b328`。
- **触发条件与现象**：小于16 MiB、只有一个段落的密集短行文本，在旧解析器中也可能产生约1 GB的进程内存占用；片段数上限未触发。
- **已验证根因**：先为所有行创建对象数组，再在块分组中保留逐行引用；限制文件大小或段落数并不限制中间对象数量。
- **修复**：[解析器](../project/src/modules/source/parser.ts) 采用逐行生成器，每个块只保留必要的首尾范围，不长期保留所有行对象。处理仍在 Worker 中执行，但 Worker 本身不能代替内存上界设计。
- **防复发**：[来源回归](../project/tests/unit/source.test.ts) 用[独立探针](../project/tests/helpers/dense-source-probe.mjs) 在128 MiB JavaScript堆限制下解析密集短行 TXT/SRT，并核对末尾行号，避免通过截断或丢行降低资源占用。该预算只约束这一合成解析场景，不是整个产品的内存承诺。
