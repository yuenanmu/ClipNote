# ClipNote 问题记录

本文持续记录值得复用的问题、已验证根因和防复发办法。后续问题在同一文件追加；相同根因补充原条目，不按每次排查新建文件。记录约束见 [AGENTS](../AGENTS.md)，任务状态和完整验证事实以[任务清单](任务清单.md)为准。

每条保持稳定编号，注明日期、触发条件、现象、根因、修复及回归入口。尚未查清的原因标为待验证；不保存凭据、私人资料或原始敏感日志。

## P001：自动化截图正常，普通启动却白屏或无法操作窗口

- **发现日期与关联**：2026-10-27，T03；修复提交 `f629115`。
- **触发条件与现象**：B 电脑执行 `npm.cmd start` 后界面空白，系统最小化/最大化/关闭无法正常操作，需要终端 Ctrl+C；此前 Playwright 页面截图正常。
- **已验证根因**：交互式 Electron 的启动器设置了 `windowsHide:true`。本机普通启动下真实 ClipNote HWND 的可见状态为 false；仅将该选项改为 false 后恢复可见，系统窗口命令和正常退出回归通过。不能把它泛化为已证明的 GPU 或缓存故障。
- **修复**：[启动器](../project/tools/start-desktop.mjs) 使用 `windowsHide:false`，保留原有 shell/标准流。交互式 GUI 不沿用隐藏后台辅助进程的启动配置。
- **验证盲区**：旧 E2E 通过 Playwright 的另一条路径启动，绕过普通启动器；CDP 页面截图和 app.close() 没有验证真实 HWND 和系统标题栏。截图真实，但验证对象不足以覆盖用户使用路径。
- **防复发**：保留[普通启动回归](../project/tests/e2e/startup.test.mjs)，直接执行 npm start，不附加调试器；检查原生可见/启用状态，验证最小化、最大化、还原和系统关闭后启动器退出。原生窗口截图与页面自动化各自提供不同证据，不互相替代。

## P002：字幕缺少分隔时静默遗漏内容或错配时间

- **发现日期与关联**：2026-10-26，T03；修复已包含于 `ae8b328`。
- **触发条件与现象**：VTT 的 WEBVTT 头部与第一条 cue 没有空行，首段被当成头部丢弃；两个 SRT/VTT cue 没有分隔空行，第二条时间和正文被并入第一片段。
- **已验证根因**：解析器直接跳过首块，并将时间行后的整个块视为正文，缺少头部内容及块内第二条时间结构的验证。
- **修复**：严格检查 VTT 头部和元数据，以及字幕块中的时间结构；无法可靠划分 cue 时明确报错，不能丢掉一段内容后仍报告导入成功。
- **防复发**：[来源回归](../project/tests/unit/source.test.ts) 同时覆盖正常字幕和这些损坏边界；验收要检查片段数量、文本和真实时间归属，不能只确认函数返回成功或 rawText 仍然存在。

## P003：文件大小受限，解析内存仍可能被大量短行放大

- **发现日期与关联**：2026-10-26，T03；修复已包含于 `ae8b328`。
- **触发条件与现象**：小于16 MiB、只有一个段落的密集短行文本，在旧解析器中也可能产生约1 GB的进程内存占用；片段数上限未触发。
- **已验证根因**：先为所有行创建对象数组，再在块分组中保留逐行引用；限制文件大小或段落数并不限制中间对象数量。
- **修复**：[解析器](../project/src/modules/source/parser.ts) 采用逐行生成器，每个块只保留必要的首尾范围，不长期保留所有行对象。处理仍在 Worker 中执行，但 Worker 本身不能代替内存上界设计。
- **防复发**：[来源回归](../project/tests/unit/source.test.ts) 用[独立探针](../project/tests/helpers/dense-source-probe.mjs) 在128 MiB JavaScript堆限制下解析密集短行 TXT/SRT，并核对末尾行号，避免通过截断或丢行降低资源占用。该预算只约束这一合成解析场景，不是整个产品的内存承诺。

## P004：完成草稿的历史标记挤占扫描上限，隐藏待恢复结果

- **发现日期与关联**：2026-10-27，T04 独立只读审阅；修复随 feat/storage 本阶段提交。
- **触发条件与现象**：本机恢复目录存在至少1,000个已完成草稿目录，真正的未完成草稿排在目录枚举后部。旧实现的恢复列表为空，但直接指定草稿 ID 仍能恢复，界面无法发现待保存工作。
- **已验证根因**：先对 readdir 结果 slice(0,1000)，再过滤 `.done`，把已经完成的墓碑算进恢复扫描额度。合成1,000个完成标记和一个待恢复草稿，修复前精确复现列表丢失。
- **修复**：[存储服务](../project/src/modules/storage/service.ts) 先过滤完成标记，再对有效待恢复草稿计数；达到显示上限时返回警告，不静默隐藏截断。
- **防复发**：[存储回归](../project/tests/unit/storage.test.ts) 同时检查草稿可发现和实际重试成功。扫描上限必须针对产品要展示的对象，不能让无关历史条目先消耗额度。

## P005：多个窗口进程共享保存设置与恢复草稿

- **发现日期与关联**：2026-10-27，T04 独立只读审阅；修复随 feat/storage 本阶段提交。
- **触发条件与现象**：重复启动使用相同 userData 的应用。两个进程各有内存 busy 锁，却共享 settings.json 和 drafts；其中一个更改目录，另一个窗口显示的旧位置可能与实际保存位置不一致。并发恢复同一草稿还可能生成两份版本。
- **已验证根因**：IPC 串行锁只约束单进程，无法约束另一个 Electron 主进程。旧实现的普通 npm start 重复启动回归因第二进程未退出而失败；审阅的服务层并发探针确认共享草稿竞争。
- **修复**：[主进程](../project/src/main/index.ts) 在设置 userData 后、创建窗口及注册业务 IPC 前请求单实例锁；第二进程退出并唤起已有窗口，最小化时还原。不同隔离测试 profile 仍可独立运行。
- **防复发**：[原生启动回归](../project/tests/e2e/startup.test.mjs) 使用相同 profile 两次执行 npm start，确认第二启动器退出0、第一窗口 PID 不变，然后继续验证系统控件。当前服务类按应用串行调用设计，不宣称支持任意多进程并发写入。

## P006：操作后的列表刷新异常逃出错误处理

- **发现日期与关联**：2026-10-27，T04；修复随 feat/storage 本阶段提交。
- **触发条件与现象**：更改保存目录后，归档状态 IPC 发生传输异常，旧实现没有显示刷新失败，Promise 拒绝可能逃出处理。普通业务错误结果还可能被静默忽略。
- **已验证根因**：finally 中 await refreshLibrary 只用另一个 finally 清除 busy，没有 catch；refreshLibrary 对非 ok 回执不报错。窗口回归替换状态 IPC 为明确抛错的处理器，修复前等不到错误提示。
- **修复与防复发**：[界面](../project/src/renderer/App.tsx) 独立处理列表刷新失败，释放忙状态并显示固定提示，不把已经确认的保存回执改写为保存失败。[窗口回归](../project/tests/e2e/storage.test.mjs) 检查提示可见、操作恢复可用和没有未处理页面异常；初次读取同样处理失败回执。

## P007：AST 识别了文件头元数据，正文渲染仍意外显示

- **发现日期与关联**：2026-10-27，T05 独立只读审阅；修复随 feat/reader 本阶段提交。
- **触发条件与现象**：Markdown 使用 `+++` 包围 TOML frontmatter，内容不进入标题树，却作为 pre 出现在正文；等价 YAML 元数据被隐藏。
- **已验证根因**：remark-frontmatter 输出 toml 节点，但[正文渲染器](../project/src/renderer/features/reader/MarkdownBody.tsx) 仅过滤 yaml，未知节点回退为显示值。解析器单元测试只检查伪标题没有进入目录，未验证实际正文。审阅的 React 静态渲染与新增窗口断言均复现该差异。
- **修复**：显式补齐 TOML AST 类型，正文同时过滤 YAML/TOML 元数据；保留其他未知文本的安全显示，不增加 HTML 执行能力。
- **防复发**：[阅读窗口回归](../project/tests/e2e/reader.test.mjs) 对两种 frontmatter 检查目录和正文：实际标题可定位，元数据值不出现。解析正确与渲染正确是两项事实，插件新增的节点类型必须在两处同时覆盖。

## P008：新增正文块 ID 与用户标题 slug 发生碰撞

- **发现日期与关联**：2026-10-27，T05 Mindmap 扩展开发。
- **触发条件与现象**：脑图为普通块生成 md-数字 ID、为虚拟根使用 map-root；用户恰有同名标题时，标题 slug 与生成 ID 重复，可能把脑图边或原文定位关联到错误节点。
- **已验证根因**：原先标题去重只覆盖标题集合，脑图/段落新增了另一个 ID 生成器，两个命名空间并未隔离。新增[脑图测试](../project/tests/unit/mindmap.test.ts) 用 map-root/md-5 标题复现5个目标仅3个唯一 ID。
- **修复与防复发**：生成块使用 @md-数字、虚拟根使用 @map-root；标题 slug 不含 @，保留原有标题锚点兼容。同一 AST 保存实际块 ID，正文和脑图共用，碰撞检查已先失败后通过；跨页同名列表项还由真实窗口检查实际焦点。

## P009：极大脑图的适应画布受最低缩放限制（已解决）

- **发现日期与关联**：2026-10-27，T05 独立审阅，Minor 非阻断问题，本轮暂缓。
- **触发条件与现象**：接近解析上限的一万标题脑图，在较低窗口点击“适应画布”时，上下边缘仍可能被裁切；仍可拖动查看或折叠主干。
- **已验证根因**：审阅只读 parse/layout 探针确认9,999个一级标题在AST上限内，布局高度679,992；600px画布最低scale=.001仍产生约680px图形。MindmapView 的适应和手动缩放共用固定最低比例，无法达到所需的更小全图比例。
- **后续办法与防复发**：将最低比例与实际 fitScale 协调，以极大树的布局尺寸和给定画布尺寸检查缩放后边界；本轮没有实施该调整，不把问题记录写成已修复。1800列表项的概览/放大窗口检查已通过，但不足以覆盖此极端尺寸。
- **后续解决**：2026-10-27 Markmap/对照扩展采用实际 Markmap.fit，取消旧 .001 下限；只在用户主动“查看全图”时执行。新增[窗口回归](../project/tests/e2e/markmap.test.mjs) 使用9,999个长中文标题（AST上限内）、10,000个图节点，确认scale<.001且实际SVG包围盒四边均在画布内；最终完整窗口35项通过。此前暂缓记录保留为历史。

## P010：长文默认全图缩放与隐藏文字，导致脑图无法阅读

- **发现日期与关联**：2026-10-27，用户实际试用T05后给出长文脑图色块截图与Markmap参考图。
- **已验证根因**：旧手工布局固定240px卡片、文字最多四行；每次展开/窗口变化自动fit整棵树，scale<.18又删除文字改为色块。先前1800节点回归只检查“交互DOM数量少”，没有验收首屏文字可读；短合成截图未覆盖用户实际长文密度。
- **修复**：替换为本地Markmap，16px完整文字/760px自然换行、段落直接入图，默认100%章节主干；展开/尺寸变化不fit，主动全图与恢复可读分开。原文定位与可调双栏支持对照阅读。特别避免Markmap.create传入data会无条件fit，改用constructor/setData。
- **防复发**：[Markmap窗口用例](../project/tests/e2e/markmap.test.mjs) 验证初始scale=1、章下长文字完整、展开不变比例、尺寸/分栏/模式切换不重置、实际对照截图及大图真实边界；不再以“DOM更少”代替阅读体验验收。

## P011：第三方渲染器的空样式节点仍触发严格 CSP

- **发现日期与关联**：2026-10-27，T05 Markmap集成窗口回归。
- **已验证根因**：markmap-view 即使embedGlobalCSS=false，构造时仍插入SVG style节点，后续写空字符串。现有style-src 'self'会拦截空内联样式，出现两次CSP控制台错误；初次新增断言明确失败。
- **修复**：应用所需Markmap CSS本地打包；在脱离文档的SVG构造实例，移除其空style后再挂入React拥有的容器，后续style引用仍保持脱离文档。不加入unsafe-inline、不关闭sandbox、不允许远程插件。
- **防复发**：同一真实窗口用例观察CSP控制台、页面错误与HTTP请求均为空，同时确认脑图foreignObject实际可见、有正常尺寸与安全转义文本。布局容器采用纵向flex，避免封装后SVG高度为零却只凭DOM存在而误判通过。

## P012：Markdown 转换扁平化遗漏标题、换行和块顺序

- **发现日期与关联**：2026-10-27，T05 Markmap独立只读审阅；原转换器继承的边界在新增段落/大纲联动中可见。
- **已验证根因**：列表通过find取首个段落或标题作为标签，既吃掉了列表内标题自己的ID，也会将代码后的段落提前；plain函数对break返回空字符串，使first+second变成firstsecond。审阅提供3个合法Markdown探针，新增[单元回归](../project/tests/unit/mindmap.test.ts) 均明确失败。
- **修复**：只提升列表第一块的段落，其余情况保留中性容器并按顺序处理；列表内标题建立局部层级且保留原ID；break返回换行。3项回归均RED→GREEN。
- **防复发**：[真实窗口](../project/tests/e2e/markmap.test.mjs) 从大纲展开并点击列表内标题，显式查看原文后确认对应标题实际焦点；同时检查图中的强制换行文本。只验证常规顶层标题和列表不足以保证AST所有有效定位目标都可导航。

## P013：对照定位的正文高亮随 DOM 焦点转移而消失

- **发现日期与关联**：2026-10-27，T05对照截图验收。
- **已验证根因**：旧正文只在:focus时标背景；点击脑图定位后再次操作脑图工具栏，焦点离开正文，选中内容虽然未变却不再高亮。新增移焦后data-reader-active断言，原实现返回null而失败。
- **修复**：正文接收共享activeId，对对应标题/段落/列表等块声明持久选中属性，CSS同时支持焦点与选中状态；保持键盘焦点用于无障碍，但不让它独占视觉选中状态。
- **防复发**：真实窗口在选中同名列表项、操作脑图居中后检查正文仍选中；公开示例双栏截图同时显示两侧对应高亮。最终完整90项本地/37项窗口回归通过。

## P014：生成文字的裸 URL 被 GFM 自动链接并干扰来源引用

- **发现日期与关联**：2026-10-27，T06独立只读审阅。
- **触发条件/根因**：模型章节/条目文字为 `https://localhost` 等裸URL或邮箱；只转义 Markdown 标点不足以阻止 remark-gfm 在文本解码后的自动链接，URL还可能吞入紧随的全角括号和来源引用开头。新增 AST 回归中应有2条来源链接却得到4～5条，已实际复现；数字实体同样无效。
- **修复**：URL/邮箱形式的词使用自适应长度反引号 code span 保留字面内容，其他文字正常转义。该类文字以行内代码显示，不授予外链；来源链接仍由应用模板生成。
- **防复发**：analysis-run.test.ts 用真实 M06 AST 检查 localhost、普通URL、www、邮箱四类输入，断言链接数量精确且全部为 clipnote-source；明确RED后修复通过。

## P015：分析结构小，生成 Markdown 的 AST 仍可能超过阅读上限

- **发现日期与关联**：2026-10-27，T06独立只读审阅。
- **触发条件/根因**：两条小于16,000字符的有效条目各含6,000个空格分隔的 `@`，输出约72 KiB，满足分析节点与字节限制；逐词 code span 却扩展为超过20,000个阅读 AST 节点。原 analyzeSource 报成功，M06 parseMarkdown 报 READER_TOO_COMPLEX，新增回归明确复现。
- **修复**：renderMarkdown 最后复用 M06 纯解析器核验实际消费者的大小/结构限制；失败转固定 TOO_LARGE，analyzeSource 保留已完成检查点。新增一条直接渲染和分析结果恢复断言，RED后通过。
- **防复发**：不靠分析 JSON 节点数推算阅读 AST；生成成功必须通过实际阅读解析限制。该依赖只调用纯解析，不读取路径、创建阅读会话或发IPC。
