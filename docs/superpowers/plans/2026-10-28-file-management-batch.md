# 文件管理与批量整理实施计划

> **执行方式：** 使用测试先行及分阶段本地提交；实现前核对仓库、分支与工作区，依赖未合并时先完成用户指定的基线整合流程。

**目标：** 用用户选定的真实资料目录和笔记目录管理文件，安全编辑 Markdown，串行批量整理并按明确关联覆盖笔记。

**现状与边界：** 当前资料仅记住最近五份来源快照；笔记目录登记路径，生成笔记使用 M05 版本库，`sourceId` 由内容决定；工作流只支持一个活动任务。现有库继续独立可读，不自动迁移；新流程不能把专用版本库内部当普通目录随意移动。用户明确要求资料不复制，新的 Markdown 一份对应一份资料；用户要求的覆盖仅限明确关联且确认的目标。

## 全局约束

- 用户先选一个真实资料根目录与一个真实笔记根目录；仅用户选择或受控根目录内的实体可操作。使用主进程文件能力与不透明 ID，渲染进程不能直接提供任意绝对路径。逐级拒绝符号链接/junction 越界；保留大小限制、原始编码、失败分类与旧版归档。
- 新资料直接使用原文件；不创建持久来源副本。文件/目录删除经明确确认后调用系统回收站，不永久删除。外部修改、权限错误、重名及消失均显式显示；不覆盖未知文件。
- 输出目标由用户选择；映射记录在应用本地设置，不包含密钥或正文。根目录内由应用执行的移动、重命名同步更新映射；外部移动无法可靠识别时标记失效并提供重新关联，不能以文件名或内容碰撞推断所有权。
- 与明确关联的笔记覆盖前显示确认；同名但归属不明时提示改名或选择其他目标。确认时记录目标校验值，写入前复核；变更则不覆盖。目标目录中准备临时文件并安全替换；替换失败保留旧文件，不在覆盖前删除原文件。用户手工编辑可保存，保存前同样检查外部变化。
- 批量开始前展示勾选清单、服务、模型、单一目标、覆盖项与费用提示；仅确认后发送。文件串行，每项独立状态；失败继续，允许取消及选取失败项重试。保存失败保留生成结果供会话内重试，不重复 AI；取消不会抹除已完成结果。

## 分阶段实施

1. **合并基线与文档：** 展示 `feat/api-file-workflow` → `main` 的候选范围、六个功能/修复提交、实际测试和 T07/T09 未验收项。仅经本次明确批准后 no-ff 合并，核对目标及结果；再从 main 建独立功能分支。任务清单 T15/T16、架构、相关模块和交接应先于业务代码更新。
2. **目录模型与文件操作：** 先测根目录选择、分页/搜索、路径遍历与链接阻挡、真实目录创建、重命名、移动、冲突、回收站及应用内映射更新；实现受控 IPC、文件 Worker 和持久根目录/映射；仅隔离测试目录，不操作真实私人目录。
3. **Markdown 编辑与新输出：** 先测创建、加载、编辑、外部冲突、短写/替换失败及未知同名保护；实现编辑保存、来源与笔记映射、可确认覆盖、失败结果重试；原 M05 旧归档与现有独立笔记登记继续可读。
4. **串行批处理：** 先测确认前零请求、仅发送已选文件、单一目标、覆盖名单、每项状态、失败继续、取消不发布迟到结果、失败项重试及写入期间外部修改；接入既有 API、分块与计时，避免多个工作流同时运行。
5. **体验：** 整合资料区和笔记区目录树、分层展开、拖动与右键移动、空态、长列表、批处理清单和进度；窄窗口与键盘可访问，保留脑图与 Markdown 定位。查看隔离窗口截图并记录用户验收。
6. **验证与交接：** 运行 `project/` 的 typecheck、build、自动测试和串行窗口回归；测试只使用合成文件与本地 HTTP 服务。记录结果、限制和真实服务/质量未测项，更新 T15/T16 子项、模块与交接；按任务实际成果提交，不推送或合并新功能。

## 关键验收

- 资料区直接显示根目录，重启后恢复选择；支持目录/文件管理、刷新及查找，大目录不一次性渲染所有节点。
- 笔记能在选定目录创建、编辑、移动和删除；外部修改与同名冲突不造成静默覆盖，旧归档和用户外部文件不受影响。
- 批次只处理用户选定文件；结果保存在统一目标，匹配的覆盖均经确认，失败/取消/重试状态真实，原文件与已完成输出保留。
- 批量请求、内容质量及费用只由用户主动在应用内真实验收；模拟测试不能代表真实模型质量、速率或费用。
