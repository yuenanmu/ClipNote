# API 文件到笔记工作流计划

**范围与授权：** 用户选择暂不调整T08订阅登录，先完成其他不依赖登录的工作。本分支feat/api-file-workflow从已合并main ba5e90d建立，实施T09的API子链；T09完整验收仍依赖T08，T08评估保留在feat/chatgpt-login。真实服务调用由用户在应用内主动发起，自动测试仅用本机合成服务。

**用户体验：** 导入文件并选定保存目录后，点击开始分析，界面展示将发送给哪个服务/模型及可能产生费用，用户再确认发送。显示处理进度、取消、错误与保存结果；成功后可在现有笔记区阅读及回查来源。重新分析产生新版本；订阅入口不在本阶段。

**实现：** 主进程只接受已导入的sourceId、可信IPC及固定动作，快照/密钥不由页面传入；读取已保存的API配置，专用Worker调用T06/T07，原始来源与凭据仅留可信进程，逐块进度只回传数量。生成Markdown由现有StorageService按独立版本协议保存；保存失败时保留完整草稿或本次内存结果并允许显式重试，不重跑AI。取消不报告成功，不自动转服务；分析失败后的分块复用和跨重启恢复留T11。

**测试：** 测试先行覆盖用户确认前零请求、无配置/目录、串行与无效IPC、真实临时文件保存/重开/引用、取消、服务失败与保存失败重试、人工修改旧版本保护；窗口测试使用本机模拟服务与测试独占目录，确认发送前接收方、界面进度及可阅读生成版本。typecheck/build/完整本地及窗口回归；真实API和语义质量由用户自行验收，不能以模拟通过标记T09全部完成。
