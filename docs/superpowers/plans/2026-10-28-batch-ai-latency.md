# 批量 AI 整理耗时与失败体验优化

> 执行：superpowers:executing-plans，当前主执行者逐阶段实现。用户明确要求先调研、更新具体方案、再修改代码；本方案是该授权内的实施选择。属于 T15 验收修复，沿用 feat/file-management，起点 d84eb95，不合并或推送。

## 目标和调查证据

用户提供三个同名副本的批次截图：两份成功，API 分别 14.2 秒和 40.0 秒、各一次请求；第三份首次为 INVALID_REFERENCE（引用无法对应原文），手动重试约三分钟后 TIMEOUT。不能将两种失败合并为一个原因，也不能仅凭文件名断定三个文件字节相同。

已查源码：batch-controller 逐份串行，无相同内容复用；每份成功后才写入 timing，异常路径丢失 metrics。provider.ts 对每个适配器请求设 60 秒 AbortSignal，但没有独立 Promise 截止/Worker 兜底；analysis/run.ts 可做一次结构修正，截断可递归三层拆分，因此整个文件可超过 60 秒。引用错误不走结构修正。提示和返回均要求每条内容带 segmentId/startOffset/endOffset；虽然用户已经取消显示来源链接，模型仍须计算 UTF-16 范围。

固定安装的 pi-ai 1.4.0 在 dist/api/openai-completions.js 给底层 SDK 传 maxRetries:0；应用也传 maxRetries:0，provider-retry 使用该值。没有证据支持“SDK 自动重试三次”。截图显示的 API 时间是各文件服务调用时间，不是排队时间。14 秒与 40 秒的服务端差异及第三次确切耗时根因尚无法追溯：现有程序未保留请求过程指标，不读取或记录私人正文/凭据，不自动付费复现。

外部调研：agent-reach/Exa 握手失败后改用内置网页工具核对一手资料。
- [Anthropic 延迟指南](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-latency)：输入/输出长度及模型影响耗时；流式反馈改善等待感受，不能据此承诺总耗时变短。
- [OpenAI Node SDK 配置](https://github.com/openai/openai-node/blob/main/README.md)：默认重试可能延长等待，但本项目固定代码明确关闭，不能套用默认值解释本例。

## 方案与取舍

选择在现有串行队列上减少重复工作、压缩引用协议并补可观测性；不自动切换模型或服务，不通过丢弃正文细节换速度，不以放宽引用有效性判定掩盖失败。直接并行会增加未知兼容服务的限流压力；单纯延长超时会加重无反馈等待，因此不作为第一方案。

1. 同批相同内容只生成一次。缓存键必须涵盖真实内容校验、来源格式、服务/模型/生成参数、整理要求和提示版本；文件操作 ID/目标路径保持独立。只有完整校验成功的结果能复用。读取每份来源确认未变后才命中；缓存仅本批内、限定容量，新批清空，失败不缓存为成功；已验证分块仅在同批内存保留用于重试。保存失败沿用既有持久恢复，不能再请求 AI。界面标注复用，不能把第一次 API 耗时复制成第二次耗时。
2. 模型只选择本次给定的短引用范围 ID，本地映射回精确 SourceRef。保持章节与内容的来源归属验证、未知 ID 拒绝、Unicode 边界及分块允许范围不变。内部 T06 契约和旧归档保持兼容，减少输出中的坐标字段与模型计数任务。不能把错误坐标任意截断到合法值。
3. 传递请求开始、等待响应、收到输出、校验、保存阶段，提供运行中 elapsed、请求次数及分块进度；失败也保留脱敏时间和错误类别。显示实际进度，不编造百分比、剩余秒数或 token 速度。仅统计数据经过 IPC，不泄露正文或密钥。
4. 每个请求的 60 秒截止必须可观测且独立于 SDK 是否及时响应 abort；超时/取消后终止本次处理、释放资源，不启动下一次收费重试。Worker 为取消提供有界退出兜底。格式修正/截断拆分仍需有显式次数与整个文件预算，达到预算报明确错误并保留已完成阶段；具体限额以合成正常长文及异常回归确定并在文档记录，不将长文全部缩成短请求。

## 实施结果与边界

已按调查→方案→失败测试→实现顺序完成。最终验证和命令唯一记录见 T15；本轮新增 batch-reuse、analysis-task 和 batch-latency 窗口用例，全部适用回归通过，分支留待用户验收。本次提交以 Git HEAD 为准。

- 实测合成同等结构、两处各两个引用的输出由旧短 segmentId 坐标格式 313 字符降至 137 字符，减少 176 字符（约 56%）。这只表示该夹具的输出负担，不代表真实模型延迟同比下降。
- 真正相同的三个副本在同批/同配置下只发一次请求，分别落盘；另一份不同内容单独请求。来源变化会拒绝复用。缓存与完成分块总额不超过 16 MiB，每类最多 100 项，新批或应用退出后清空；跨重启分析恢复仍未实现。生成成功但保存失败继续沿用持久待保存结果。
- API 提示版本 t15-ranges-v3；模型选择 r1/r2 范围 ID，可信进程还原后仍做完整校验。保留旧坐标对象输出兼容，错误对象不会被自动修正成合法引用。语义忠实性仍需真实样本验收。
- 每次请求最多 60 秒，整个文件预算为 min(30 分钟, max(3 分钟, 原始计划分块数 × 90 秒))；请求次数上限为 max(8, 原始分块数 × 4)，格式修正/截断拆分共用上限。达到上限明确失败，不保存残缺 Markdown；复杂截断文件可能需要调高输出预算或拆分资料。长文件不被统一压成 3 分钟，但最多 30 分钟。内部缩短预算只用于合成测试，页面无法传入任意预算。
- 单次超时不自动重试；同批手动重试可续用已完整校验的原始分块（当前正在递归拆分且尚未完成的原始块仍需重做）。Worker 取消直接终止，异步失败保留指标。后台不保存用户正文诊断日志，界面只展示阶段、耗时和次数。
- 独立只读审阅已尝试，但因服务用量限制未取得结果，不记为通过。主执行者完成代码/契约与验收清单复核；真实服务当次三分钟超时的精确原因仍无法追溯，不推断为 SDK 默认重试或三个副本必然引起。
